# TaskReviewPlan

작성된 plan 문서 3종을 구현 전에 검토하고 개선점을 제안할 때 사용한다.

## 사용 예시

- `$TaskReviewPlan 현재 plan 검토해줘`
- `$TaskReviewPlan 구현 전에 누락/과설계 여부를 봐줘`

## 검토 자료

| 파일 | 확인 내용 |
|------|----------|
| `.codex/plan/plan.md` | 목적, 범위, 설계 결정, TaskList |
| `.codex/plan/context.md` | 사용자 요청 원문, 배경, 결정 근거 |
| `.codex/plan/checklist.md` | 실행 순서와 검증 항목 |

## 리뷰 관점

### 1. 목적 정합성

- context.md의 사용자 요청과 plan.md 구현 방향이 일치하는가?
- TaskList가 목적 달성에 충분한가?
- 요청에 없는 기능이 포함되어 있지 않은가?

### 2. 사용자 Flow

- 사용자 관점에서 흐름이 자연스러운가?
- 에러, 로딩, 빈 상태가 고려되었는가?
- 사용자에게 필요한 피드백이 있는가?

### 3. 유지보수

- 설계가 기존 코드 패턴과 일관성이 있는가?
- 향후 변경 시 수정 범위가 적절한가?
- 불필요한 추상화나 레이어가 있는가?

### 4. 성능

- DB 쿼리, 대량 데이터, 반복 처리 관련 위험이 있는가?
- 캐싱이나 지연 로딩 전략이 필요한가?
- 현재 요구사항 대비 성능 설계가 과하거나 부족하지 않은가?

### 5. 오버엔지니어링

- 요구사항 대비 복잡도가 과한 부분이 있는가?
- 현재 필요하지 않은 기능이 포함되어 있는가?
- 더 단순한 구현 방법이 있는가?

## 출력 형식

```markdown
# Plan 리뷰 결과

## Critical 이슈

| # | 관점 | 내용 | 제안 |
|---|------|------|------|

## Warning

| # | 관점 | 내용 | 제안 |
|---|------|------|------|

## 확인 질문

- ...

## 요약

- Critical: X건 / Warning: Y건
- 적용된 리뷰 관점:
- 권장 수정 사항:
```

Critical 이슈가 있으면 구현 전에 수정하도록 구체적인 변경 방향을 제안한다.
